Everything a transport needs. Built and measured from first principles.

Reliability layer

Selective Repeat with 64 packets in flight, per-packet timers and cumulative + selective ACKs.

The wire format

24 bytes of header. Every bit has a job.

Big-endian, drawn the way RFCs draw it. Select a field to see its value in a real packet produced by the encoder.

Never fragmented1,268

bytes on the wire at most, below IPv6's 1,280-byte minimum MTU. Losing one IP fragment would lose the whole datagram.

Per packet

CRC-32

Catches every single-bit error (tested exhaustively), but anyone can recompute it after tampering.

Per file

SHA-256 + optional HMAC

SHA-256 proves the file is bit-identical. Only the HMAC with a shared key proves who sent it.

TCP's answer: RFC 6298

Jacobson / Karels, 1988
# every valid sample R (never from a resent packet: Karn) RTTVAR = ¾·RTTVAR + ¼·|SRTT − R| SRTT = ⅞·SRTT + ⅛·R RTO = SRTT + 4·RTTVAR # doubles on timeout

Five ways to decide when to resend

A formula, two models, a smarter way to notice loss, and both together.

Both models predict the 95th percentile of the next half-second of round trips, a threshold about 95 % of packets will beat. They can only nudge the formula within safe bounds, and fall back to it whenever they are unsure.

Version 2, built from version 1's mistakes

  • Asymmetric loss. A too-short timeout costs far more than a too-long one, so v2 uses quantile loss: under-predicting costs × more.
  • Trained on its own behaviour. v1 only saw traces recorded under the formula. v2 also learned from transfers driven by v1 itself.
  • Calibrated end to end. v1 picked its safety margin offline. v2 picks quantile and margin by running real validation transfers, with the rule fixed in advance: no more than 1.15× the formula's wasted resends.

The lesson

More accurate on paper did not mean better on the wire. A timeout is a decision inside a feedback loop, not a forecast.

Offline: held-out test runs

Error = mean |timeout − target| in ms. Early = share of upcoming packets whose RTT exceeds the timeout.

Why the paper result did not transfer

  • Errors arrive together. When a slow period begins, every in-flight timer fires at once; one short timeout becomes dozens of resends.
  • Feedback. Each early timeout makes a packet ambiguous under Karn's rule, so history thins out exactly when conditions change.
  • Unseen conditions. A v1 model that never saw the changing network was less accurate on it than the plain formula ().
  • The bigger lever was elsewhere. Detecting loss from the ACK pattern (RACK) avoids many timeouts altogether.

Engineering

Tested like it matters. Because it does.

Automated tests

Packet fuzzing, every single-bit flip, hand-checked RTO maths, RACK timing, simulator determinism, crashes, path traversal, HMAC and the live server.

Bugs found by testing3

Runaway backoff (22 s → 4.3 s transfer), a filename clash caught by independent re-hashing, and a naive fast retransmit that fired thousands of false resends, replaced by RACK.

Runtime dependencies0

Sender, receiver, proxy, both models and the live lab run on the Python standard library alone.

Conclusion

Reliable delivery, every time. Smarter timeouts, only sometimes.

Limits we are honest about

  • One machine over loopback, with delay simulated in user space: no queueing, no bandwidth limit, no cross traffic.
  • No congestion control, so the protocol is not fair to other traffic on a shared link.
  • Models trained and tested on the same simulator; real-network performance is unproven.
  • 10 seeds per network: strong for large effects, weak for differences of 1–2 %.
  • On the loss-free network the sender is CPU-bound in Python: v2's 300-tree model and RACK's bookkeeping cost about 2 % goodput there. The three new strategies were also run after the first three, not interleaved.
